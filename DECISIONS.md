# Design decisions

A log of significant choices made in this project, with a short reason for each.
New entries are added at the bottom. Earlier decisions are not edited – if a decision changes, a new entry explains why.

| Date | Decision | Reason |
|------|----------|--------|
| 2026-10-01 | Public GitHub repository | Portfolio visibility, and GitHub Actions minutes are free and unlimited for public repositories. |
| 2026-10-01 | MIT license | Short, permissive and the most widely used license on GitHub. Apache 2.0's explicit patent grant is not needed for this project. |
| 2026-10-01 | uv with pyproject.toml and uv.lock | The lockfile makes environments reproducible locally and in CI, installs are fast, and pyproject.toml is the Python packaging standard. |
| 2026-10-01 | Python 3.13, pinned in .python-version | Stable and supported by all planned libraries. Pinning the minor version allows patch updates but prevents accidental upgrades. |
| 2026-10-01 | README.md in each folder instead of .gitkeep | Git does not track empty directories. A README solves this while documenting what each folder is for. |
| 2026-10-01 | Hand-written .gitignore instead of GitHub's template | Shorter and fully explainable. Includes `*.env` as an extra safeguard against committing secrets. |
| 2026-10-01 | LF line endings enforced via .gitattributes | Consistent line endings across Windows development and Linux-based CI, regardless of each developer's Git settings. |
| 2026-10-01 | pytest and ruff set up from the start | Cheap to adopt before any code exists, and ensures consistent formatting and a working test setup for CI. |
| 2026-10-01 | English for code, file names, commits and docs | Industry standard and accessible to international colleagues and reviewers. |
| 2026-10-01 | Deferred: docs/ folder, pre-commit hooks, Conventional Commits | Not needed yet (YAGNI). Will be added if and when the project requires them. |
| 2026-10-01 | GBFS Client-Identifier: `lucajuul-bysykkelforecast`, stored as env var BYSYKKEL_CLIENT_ID | Oslo Bysykkel requires a Client-Identifier header in the format name-app. Not a secret, but kept in config so it can change without code changes. Data is licensed under NLOD 2.0 (attribution required in README). Feed URLs are hardcoded instead of read from gbfs.json, for simplicity. |
| 2026-10-04 | Trigger the collector from cron-job.org via the GitHub API (workflow_dispatch) every 15 min; keep `schedule` as a fallback | GitHub's scheduled runs were heavily throttled: measured gaps of 2–6 hours instead of 15 minutes, too sparse for 15-minute predictions. An external cron calling workflow_dispatch is free and needs no code changes. It uses a fine-grained token scoped to this repo with Actions read/write only, expiring 2027-01-02. Dispatch-triggered runs are also not disabled after 60 days of repo inactivity. Rejected: accepting the gaps (poor data), running locally (laptop must stay on), moving to another platform (rewrite). |
| 2026-10-30 | Export the database once to local Parquet files in data/ (`ml/export_data.py`); all analysis reads the files | Neon's free compute is close to its monthly limit. One full export costs a few seconds of compute; repeated notebook queries would cost far more. Parquet keeps column types (timestamps with time zone) and is fast to read. Full re-export instead of incremental, for simplicity – the data is small. |
| 2026-10-30 | Analysis starts 2026-10-04 18:00 Oslo time | Before cron-job.org took over, GitHub's throttled schedule left gaps of 3–6 hours. |
| 2026-10-30 | Regular 15-minute grid per station with forward fill (`ml/grid.py`) | Only changed rows are stored, so a missing row means "unchanged" and forward fill recovers the true value. Runs are floored to their 15-minute slot; if several runs share a slot, the latest wins. Times are kept in UTC to avoid daylight saving issues. |
| 2026-10-30 | Gaps: short known outages listed in code (5 Oct 21:05–23:32), plus any silence over 3 hours; gap slots get `is_gap = True` and missing values | Quiet nights produce 1.5–2.5 hours with no changed rows although the collector ran (verified in the Actions run history), so silence alone is not a gap. Values inside gaps are set to missing so they cannot leak into training or evaluation. Values after a gap are still carried forward, because the collector compares against the last stored row. |
| 2026-10-30 | Analysis libraries (pandas, pyarrow, matplotlib, ipykernel) in the dev dependency group | The collector workflow installs with `--no-dev`, so it stays small and fast. |
| 2026-10-30 | Deferred: `collector_runs` table logging every run | Would make gap detection exact, but the Actions run history and the 3-hour rule are good enough for this project. |
| 2026-10-30 | Exploration notebook committed with outputs | GitHub renders the plots directly, so reviewers can read the findings without running anything, and the data is not in the repo. Cost: noisier diffs and a larger file, acceptable for a notebook that rarely changes. Outputs contain no secrets. Rejected: stripping outputs (nbstripout), which suits notebooks that change often. |
| 2026-10-30 | Fixed train/test split in `ml/config.py`: train on pairs whose target is before Fri 23 Oct 00:00 Oslo time, test on origins from 23 Oct to 30 Oct 00:00 | A fixed date (not "last 7 days") keeps the test set identical in Phase 4 even after a new export. One test week contains every weekday once, which is the minimum to judge the weekly pattern; 18 days of training gives 2–3 examples of each weekday and time. A longer test week would give a more reliable error but leave too few training weeks. The test week includes the end of daylight saving time (25 Oct). |
| 2026-10-30 | Training pairs must have their *target* before the split, not just the origin | Otherwise a pair at 23:45 the day before the split with a 60-minute horizon learns from a test-period value. Covered by a test. |
| 2026-10-30 | Evaluate only valid pairs: both slots outside gaps, station installed, renting and returning at both, capacity known, and not frozen (bikes and docks unchanged for 72 h, looking backwards only) | Gap values are unknown, and inactive or frozen stations are trivially "unchanged", which would flatter every model. The frozen rule uses only past data, so the same rule can run in production; it covers the 2 stations that stopped changing. All models are scored on exactly the same pairs. |
| 2026-10-30 | Models predict bikes only; docks = (bikes + docks now) − predicted bikes | Phase 2 showed docks change exactly as much as bikes. Using the current total instead of nominal capacity stays right when some docks are out of order. Docks MAE is still reported to confirm it. |
| 2026-10-30 | Clip predictions to [0, capacity], but never below the current value when that is above capacity | Some stations can report more bikes than capacity; clipping "unchanged" there would add error that is not the model's. |
| 2026-10-30 | Three baselines with one interface (`fit(train_pairs)`, `predict(pairs)`): unchanged, same local time last week (falls back to unchanged when missing), current value + mean training change per station × weekday × time of day × horizon | Simple and explainable reference points for Phase 4. Weekday and time of day use Oslo local time, so commuter peaks line up across the daylight saving change; "last week" also uses local wall-clock time. |
| 2026-10-30 | Report MAE for all hours, daytime (07–21) and weekday rush (07–09, 16–18), by local time at the origin | Most slots at night never change and pull the overall MAE down. The origin is when the user asks, so subsets follow it. |
| 2026-10-30 | Results saved to `results/baselines.csv` (long format) and `results/baselines.md` | Phase 4 can load the CSV and compare directly; the Markdown is readable on GitHub. |
| 2026-10-30 | `unchanged` is the baseline Phase 4 must beat (MAE 0.221 / 0.394 / 0.669 bikes overall, 0.588 / 1.012 / 1.667 in weekday rush) | It beat both other baselines in almost every subset. Explanation of all results in `results/README.md`. |
| 2026-10-30 | Keep deriving docks from the current total, not from nominal capacity | bikes + docks equals capacity in only 25.6 % of active rows and is constant at no station, yet docks MAE derived from the current total matches bikes MAE. |
| 2026-10-30 | Keep the frozen-station rule at 72 h; it found 5 stations (430, 473, 625, 4552, 5424), not 2 | The rule looks backwards, so it adapts as stations stop or restart; no need to list stations by hand. |
